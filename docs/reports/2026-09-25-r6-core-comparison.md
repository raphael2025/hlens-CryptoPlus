> 命令：`uv run python scripts/run_backtest.py`（同 R5，一次跑三组）。配置 `9.0-core.1`，成本全开。

- **4H 门控减少了亏损，但没有创造优势**：挡掉 72% 的交易，期望值从 -0.14R 变成 -0.10R，两者区间大幅重叠，差异不显著。
- no_gate 在 2023 年为正（143 笔、+38R），2020-09..21 与 2022 大亏：没有门控时结果完全由行情段落决定。
- **sweep 变体样本不足**（23 笔），不能下任何结论。

## 2. 停止条件（计划 §4）

> 若 V9-core 在开发集上的期望值区间包含 0，且净夏普不优于 B1，则判定「4H / 1H / 15m 结构本身没有增量」，出报告并停止；不允许靠加机制层去救一个无效的核心。

- 期望值区间 [-0.46, +0.31] **包含 0** ✔
- 净夏普 -0.34 **不优于** B1 最好的 1.14（也不优于 6 个 B1 里的任何一个正夏普版本）✔

**停止条件触发。** 按计划：
1. **不做 R7**：H1–H10（OI / CVD / 现货 / 资金费率 / 强平代理 / 多空比 / 阶段 / 回调质量）不加在这个核心上。
2. **不碰留出集**：`9.0-core.1` 没有值得确认的东西。
3. 结论记为：**按当前规则实现的 V9 核心结构，在 2020-09 → 2023 的 BTC 永续上扣成本后没有正期望，且不如简单的日线趋势基线。**

## 3. 这个结论不等于什么

- 它不等于「V9 的思路错了」，只等于「这一版规则没有抓到它」。R5 的诊断指出了三个与框架本意不一致的实现问题：移动止损太紧（只兑现 53% 的浮盈）、做空一侧持续亏损、4H 状态频繁闪烁（R3）。
- 它也不等于「机制层没用」——机制层还没测。但计划规定机制层只能否决入场；在一个负期望的核心上做否决，最多把亏损变小，这正是计划禁止的「救核心」。

## 4. 下一步（若继续）

只允许**一次**有预先写明理由的改版 `9.0-core.2`，改动必须在跑之前写进计划，理由只能来自框架原文或 R3 / R5 的诊断，而不能来自「试几个参数看哪个好」；改完在开发集上跑一次，再在留出集上**只跑一次**做最终判决。因为改版的动机来自开发集，开发集上的改善不算证据，只有留出集的结果算数。
