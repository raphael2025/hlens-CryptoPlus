## 1. 一句话

**hlens CryptoPlus 是多所加密情报与量化研究系统：用棱镜把一个市场拆成价格、订单流、持仓、费率、流动性、参与者等多个面，各面之间的分歧就是信息；只给状态、历史分布与可复现的研究结论，不给动作。**

第一切片：Binance（CEX）+ Hyperliquid（DEX），永续合约。品牌语 "See more · Think deeper · Trade wiser" 只是标语，产品文案一律遵守 §4.1 禁止词表。

## 3. 用户

主：**公开网站与社群**——手机优先的永续交易者，中英双语，看状态、历史分位与一句人话答案，不登录即可用。次：**量化 / Agent 开发者与研究者**——要证据、要能自己复核的人（API、MCP，付费主体）。**不服务**：要喊单、要目标价、要跟单的人。

## 4. 原则（不可协商）

1. **只描述，不建议。** 禁止词：建议、可以考虑、适合、机会、目标价、止损设在。允许：处于、转为、满足 X 条规则、历史分布数字。
2. **"策略"的边界**：在 hlens，策略 = **可复现的研究与回测**，结论必须带样本量 n 与证据标签，公式与数据窗口公开、可重跑。**永远不是**交易信号、喊单、目标价或建议。标语里的 "Trade wiser" 指用户拿证据自己决策，不构成本项目给出决策。
3. **证据标签**：`已验证` / `站内自验证`（预注册分组，n ≥ 100，FDR 校正后显著）/ `启发式` / `观点` / `样本不足` / `模型估算`。
4. **样本规则**：n < 10 的面置灰不显示数值；n < 30 不显示百分比；任何统计显示 n。
5. **新鲜度预算**（分面）：价格与费率 ≤ 60 秒、OI ≤ 2 分钟、多空比 ≤ 15 分钟、大户 ≤ 5 分钟（M5 起适用）、爆仓聚合 ≤ 5 分钟；超限的短语置灰并显示 `as_of`。
6. **公式公开、规则版本化**：阈值改动走 PR，附校准报告，进变更日志。
7. **不显示零冒充数据**；源故障显示灰色与最后成功时间。**能力三问不合并**：`supported` / `mode` / `completeness` 分开声明；交易所限流的爆仓流一律 `lower_bound`。
8. **不碰用户资金**；无交易执行、无 key 托管、无收益分成。
9. **无广告；返佣明示**，返佣入口只出现在 `/sources`；美国与受制裁地区按 Cloudflare 国家头隐藏。
10. **钱包政策**：不做身份关联与跨链画像；措辞去情绪化；提供 opt-out 邮箱，7 日内脱敏。
11. **对外承诺尽力而为，无 SLA**；`/status` 公示 30 天真实可用率。

## 7. 架构与基础设施

### 7.1 部署形态：一台 VPS

东京主库 + 新加坡副本的双机设计**撤回**（双机 HA 列入以后）。单台 VPS，Docker Compose **四个容器**，不是旧计划的 19 个：

`postgres`（PostgreSQL 16 + TimescaleDB，唯一存储）· `collector`（采集进程 REST + WS，写库并导出版本化 JSON）· `api`（FastAPI，**M3 才起**）· `cloudflared`（Cloudflare Tunnel 出口）。

另两台/处不变：**hub（笔记本）**——`hlens-hub` 生产采集与 GitHub `hlens` 档案系统继续以 systemd 运行，**不容器化、不进 CryptoPlus 的 compose**，只读历史导入源（**M5 起使用**）与离线校准机；**GitHub Pages**——线上静态站，同时是主站的**降级模式**（每 30 分钟推 `latest.json`）。

约束：**VPS 的公网出口 IP 必须与 hub 任一 worker 不同**（交易所限速按出口 IP 记账）。hub 上两处安全问题（`hub.env` 明文 secret、admin 端点无鉴权绑 0.0.0.0）待 raphael 处理，阻塞 M5。Cloudflare 免费层；R2 备份约 1.5 美元/月；Sentry、Better Stack、Resend 免费层。恢复目标（单机、每日备份的真实数字）：**RPO ≤ 24 小时**（最坏丢一天自采数据；要收紧就把 WAL 归档也推到 R2，M1 不做）、RTO 约 2 小时（新机器 + compose + 从 R2 恢复）；无 SLA。v3.1 的"RPO ≤ 5 分钟"依赖双机副本，已随双机设计一并撤回。**仍阻塞在 raphael**：VPS 规格（CPU / 内存 / 磁盘）、出口 IP、Docker 版本、回收政策；域名、CoinGecko Demo key、`supportEmail`。

### 7.2 工时假设

raphael 说每周 20+ 小时。**按 15 小时/周排，25 视为上行**。事实记录：09-12 → 09-19 这一周提交数为 0。里程碑只给小时数，**不折算成日历日期**。

### 7.3 现在就要定死的五个接缝

这是"模块化、留好接口、防止大改动"的全部答案——只有这几处改起来贵，其余等做到时再定：

1. **归一化数据契约**——`packages/hlens-core` 的 contracts。**已存在**。
2. **带能力声明的适配器协议**（`supported` / `mode` / `completeness`）——**已存在**；加一个交易所 = 加一个文件。逐笔成交与盘口深度**现在就声明为能力并标 unsupported**，M4 只补实现、不改协议。
3. **模块之间只通过数据库表（与契约）说话，不互相 import**：collector → store → compute → serve。任何一层都能单独重写。
4. **高频数据（逐笔、盘口）单独建表 + 按币白名单**，M4 打开它时不碰分钟级链路。
5. **钱包数据有自己的协议**，与行情 `VenueAdapter` 分开，M5 不改 M1 的代码。

外加前端接缝：**前端只读版本化 JSON**，除此不碰后端——所以 M2 升级现有静态站、以后换任何前端框架，都不动后端。
