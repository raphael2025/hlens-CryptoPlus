- 09-19 **生产宿主 = hub 那台机器，不买 VPS**。连带：与旧采集器共用一个出口、**共用一份限速预算**（原"出口 IP 必须与 hub 不同"这条硬约束彻底反转）；停电与 ISP 中断成为常规失效模式；月成本上限松绑。
- 09-19 **PostgreSQL 统一钉 18.6+**（dev 与 prod 同大版本；`pg_dump` 不能跨大版本向下恢复，否则恢复演练是假的）。
- 09-19 **备份只用 NAS，经 Tailscale 从生产机拉取**，不使用对象存储；NAS 在异地，异地性质成立。连带：生产机必装 Tailscale，SSH 随之改走 Tailscale。
- 09-19 **告警第二渠道 = 外部心跳服务触发 + 自建邮件服务器投递**；判定逻辑留在第三方，投递管道自有。
- 09-19 **大额账户 = 按账户价值取 TOP N 的排行榜口径**，N 取到样本 n ≥ 100 为止，规则公开、用户不可调。
- 09-19 **M4 的逐笔滚动留存 ≤ 7 天**，30 天分位算在派生的分钟表上；门控试运行 7 天改 14 天。
- 09-19 **「我的仓位」的保证金参数由用户自己填**，强平价按该所公开公式计算；因此它天然是纯本地的。
- 09-19 **月成本上限 ≤ 25 美元**（生产机自有硬件后重设；它的作用不是省钱，是继续充当“要不要再加一个服务”的拒绝理由）。
- 09-19 **生产机加装 UPS，M1 验收保留「连续 14 天绿色 ≥ 95%」**；UPS 是上机前置。UPS 解决停电、解决不了 ISP 中断，因此另设两个诊断口径上状态页。
